# 2026-10-18

## IPTV 自动狩猎引擎（iptv-everyday）从零搭建

- 目标仓库：Gitee `ywyw2020/iptv-everyday`（本地已有 git，origin 仍指 GitHub，尚未加 gitee remote）。
- 已实现完整 7 模块：`discover_sources`（4 渠道：GitHub Search / 递归裂变 / Awesome+topic / DDG）、
  `fetch_sources`、`deduplicate`、`validate_streams`（HTTP→ffprobe→ffmpeg 三层）、
  `retire_sources`（淘汰+墓地30天回访复活）、`generate_m3u`、`push_to_gitee.sh`。
- 配置：20 线程验证、每频道保留 3 条（+2 冗余候选）、Asia/Shanghai、六类分组。
- 关键设计决策：
  - sources 以 playlist_url 为键；连续失败计数**统一由 retire 每日结算一次**（last_counted_date 去重），
    validate 只写事实字段（last_valid_count / last_verified），避免重复计数。
  - 流水线顺序保持 discover → retire → fetch → dedupe → validate → generate → push：
    淘汰用"昨夜"数据，复活在 fetch 前，复活源当晚即可被抓取。
  - Search API 与核心 API 配额分开：search 调用不做 min_rate_limit 预检，避免误休眠；
    匿名模式 min_rate_limit 自动降到 5；限流最多休眠 `max_rate_limit_retries` 次后熔断。
  - 无 ffmpeg 时降级验证并显式告警，validate 无数据时返回 0（不阻断流水线）。
- 测试方式（本机沙箱）：mock GitHub API 测发现层（准入门槛/文件树过滤/raw 拼装），
  mock subprocess 测三层验证（通过/2层失败/3层失败/超时/404），本地 http.server + 本地 m3u
  跑通 fetch→dedupe→validate→generate，bare repo 跑通 push（含空变更跳过）。
- 环境限制：本机无 ffmpeg；沙箱出口 IP 的匿名 GitHub 配额已被耗尽（403），
  真实 search 渠道未跑通，需 `GITHUB_TOKEN` 在生产环境验证。
- 未提交 git：工作区留待用户自己 commit / 加 gitee remote。
